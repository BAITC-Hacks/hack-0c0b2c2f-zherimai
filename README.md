# Zherimai

Проект команды DalaAI для хакатона BAITC Hacks. В основе проекта — граф внутрибанковских переводов за июль 2026 года. Репозиторий пока содержит описание исходных данных; код и файлы датасета ещё не добавлены.

## Данные

Граф построен от 81 исходного клиента (`seed`) обходом исходящих переводов на глубину до четырёх колен. В выборку включены переводы за период **1–31 июля 2026 года** с порогом по сумме **от 5 000 KZT**.

| Показатель | Значение |
| --- | ---: |
| Исходных клиентов | 81 |
| Уникальных клиентов в графе | 2 248 |
| Уникальных направленных пар «плательщик → получатель» | 3 119 |
| Отдельных транзакций | 4 840 |

Новые узлы по глубине обхода:

| Колено | Новых узлов |
| ---: | ---: |
| 0 — исходные клиенты | 81 |
| 1 | 472 |
| 2 | 462 |
| 3 | 789 |
| 4 | 444 |

### Структура датасета

Описанные ниже пути относятся к исходному датасету. Файлы `data/*.parquet` пока отсутствуют в репозитории.

**`data/nodes.parquet`** — одна строка на каждого уникального клиента, включая исходных.

| Поле | Тип | Описание |
| --- | --- | --- |
| `gid` | `int64` | Идентификатор клиента |
| `depth` | `int` | Минимальное колено первого появления; `0` для исходных клиентов |
| `is_seed` | `bool` | Признак исходного клиента |

**`data/edges.parquet`** — одна строка на направленную пару клиентов; переводы между ними агрегированы за весь период.

| Поле | Тип | Описание |
| --- | --- | --- |
| `src` | `int64` | `gid` плательщика |
| `dst` | `int64` | `gid` получателя |
| `sum_kzt` | `float64` | Общая сумма переводов пары в KZT |
| `n_tx` | `int64` | Число транзакций между клиентами |
| `depth` | `int8` | Колено, на котором обнаружено ребро (1–4) |

**`data/transactions.parquet`** — отдельные транзакции для найденных рёбер, без агрегации.

| Поле | Тип | Описание |
| --- | --- | --- |
| `src` | `int64` | `gid` плательщика |
| `dst` | `int64` | `gid` получателя |
| `date` | `date` | Дата транзакции |
| `sum_kzt` | `float64` | Сумма транзакции в KZT |

## Особенности выборки

- Рёбра направлены от плательщика к получателю.
- Обход выполнялся только по исходящим переводам, поэтому граф не описывает все связи клиентов банка.
- `depth` узла — минимальная глубина его обнаружения, а `depth` ребра — глубина, на которой найдено это ребро.
- Агрегированное ребро может включать несколько транзакций; для анализа отдельных переводов нужен файл `transactions.parquet`.
