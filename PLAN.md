# План решения «Граф денег»

## Цель и продукт

Дать AML-аналитику воспроизводимый ответ: кого проверить первым, какие наблюдаемые переводы это обосновывают и каких данных не хватает для вывода. Результат — очередь проверки, финансовые сообщества, карта направленных потоков и карточка любого gid с формальным правилом роли. Роли описывают наблюдаемое поведение; преступная цель и виновность по этим данным не устанавливаются.

23.09.2026 капитан подтвердил: на платформе выбран «Граф денег»; официальный репозиторий — BAITC-Hacks/hack-0c0b2c2f-zherimai; выданные parquet разрешено включать в него. Коммиты текущей разработки выполняются от настроенного аккаунта a4ns. Владельцы назначены следующим запросом капитана: A — a4ns, B — Alexandr, C — Erzhan. Подробные задания и границы файлов: `docs/assignments.md`. Подготовка выступления отложена: сначала качество решения.

## Уже есть проверенная основа

- Три исходных parquet → проверка схем и агрегатов → направленные метрики и даты → сообщества → роли → приоритет → объяснения → CSV и локальный экран.
- 2 248 узлов, включая 19 изолятов; 49 групп, из них одна техническая группа изолятов; топ-50. Все обязательные выходные колонки сохранены.
- Обрыв 4-го колена, неполные входящие seed и неизвестные остатки отражены в правилах и карточках.
- Формальные пороги: 5 плательщиков для consolidator; 10 получателей для distributor; отношение 0,8–1,2, вход от 50 тыс. и не-seed для transit. Координатор требует также q99 центральности. Полные условия и порядок в README и aml/roles.py.
- Временное сопоставление без повторного использования исходящей суммы; циклы; сценарии удаления топ-5/10/20; запросы недостающих данных.
- 10 тестов, проверка повреждённых входов/выходов, побайтная воспроизводимость CSV. Проверенный холодный запуск в новом окружении на текущем macOS — 15,71 с, лимит ТЗ — 300 с.
- Помощник сейчас детерминированный: вызывает заданные операции по поддерживаемым формулировкам. Внешний LLM не подключён.

## Что именно проверять в методике

1. Упорядочение ролей не должно скрывать важный второй паттерн: крупная рассылка остаётся видна в метриках, даже если основная роль coordinator или consolidator.
2. q99 центральности выделяет структурных посредников, но не доказывает роль организатора. «Чёрный ящик» не добавляется; порог и значения должны быть доступны рядом.
3. Временной показатель показывает совместимость дат и сумм, а не происхождение тех же денег. Операции одного дня не имеют известного порядка.
4. Нулевые исходящие на depth=4 не интерпретируются как удержание денег. При depth<4 также неизвестны наличные, межбанк и подпороговые операции.
5. Удаление узлов оценивает достижимость в наблюдаемой сети. Отдельно учитывается удаление самих получателей и потеря маршрутов к сохранившимся получателям.
6. Чувствительность оценивается честно: если топ или кластеры меняются сильно, это ограничение и основание для проверки, а не повод подогнать желаемый результат.

## Условие для дополнительного AI

Приоритет ассистента — ускорить проверяемый запрос, например «найди общих получателей этих seed» или «покажи путь между узлами». Список разрешённых операций: get_node, common_receivers, paths, cluster_summary. LLM не назначает роли, не выдумывает клиентские признаки и не заменяет расчёт.

Подключать внешний LLM имеет смысл только после P0, если есть проверяемый доступ и остаётся время на ошибочные/неподдерживаемые запросы. API и передача графовых сведений требуют отдельной конкретной настройки. Без неё сохраняем текущий локальный помощник и честно описываем его ограничения. Наличие LLM само по себе не считается улучшением и не гарантирует дополнительных баллов.

## Среда и оставшиеся неизвестные

В Положении, инструкции и ТЗ из Context не указаны версия Python, ОС, архитектура и способ установки зависимостей у экспертов. Указаны автономное чистое окружение, подробный README и запрет обязательного облака/GPU/платных сервисов. Предположение «у них последние версии» не используем.

Текущая проверенная среда: macOS ARM64, Python 3.13.2, закреплённые версии пакетов. Локальный wheelhouse подходит этой среде и не включён в Git; для другой ОС/архитектуры требуется совместимый комплект. Если целевую среду установить не удастся, это остаётся явно указанным риском сдачи, а не подтверждённой переносимостью.

Выбор кейса и разрешение включить данные подтверждены капитаном. Не подтверждены: целевая среда экспертов; ручной визуальный просмотр экрана; итоговая подача на платформе.

## Критерий готовности

Решение готово к технической сдаче, когда новый пользователь выполняет README, получает правильные схемы и все 2 248 узлов менее чем за 5 минут, находит любой gid, объясняет его роль по числам и видит границы наблюдения. Дополнительные функции включаются в описание только после проверки. Точность классификации не заявляется: размеченных истинных ролей нет.
