# Набор вопросов для оценки планировщика

`docs/ai-eval-cases.json` содержит **12** примеров на текущих данных: 3 карточки, 3 пути, 2 запроса общих получателей, 1 сводку кластера, 2 неподдерживаемых задачи → help и 1 неизвестный gid → локальная ошибка до сети. Максимальная длина вопроса — 93 символа. При полном онлайн-прогоне ожидается не более **11 API-попыток**; неизвестный gid не должен вызывать API.

Идентификаторы выбраны алгоритмически по сохранённым данным: карточка — первый не-seed по priority; путь — первая по приоритету пара с направленным путём длиной ≥2 и без обратного пути; общие получатели — два плательщика выбранного узла с максимальной входящей степенью; кластер берётся у выбранной карточки. Неизвестный gid — первое свободное число выше максимума набора. Правила и SHA-256 входов сохранены в JSON. Это тестовые фикстуры; gid не используются для назначения ролей.

Для выбранной пары путь вперёд содержит 5 рёбер, обратного пути нет. Обе формулировки должны всё равно выбрать `paths`: существование пути проверяет локальная операция, а не модель. В третьей формулировке цель названа перед источником — правильный порядок аргументов обратен порядку упоминания gid.

## Как оценивать

- Передавать приложению только `case.question`. Не отправлять модели весь JSON, ожидаемые планы, сведения о существовании путей, метрики или результаты локальных операций.
- У 11 семантических случаев требовать `online_semantic_plan_local_execution`, правильный action, cluster_id и набор gid. Для paths требовать точный порядок «источник, цель»; для карточек и общих получателей порядок несущественен. Алиасы восстанавливаются по порядку первого упоминания gid в вопросе.
- Локальный fallback на сетевой ошибке не считается успешным выбором модели, даже если локальный помощник смог ответить.
- Для `unknown_gid_preflight` ожидается `offline_deterministic`, `fallback_reason=unknown_local_gid`, отсутствующий plan, локальный get_node с ошибкой и ноль API-вызовов. Поэтому expected_action=null и expected_gids_order=[].
- Использовать общий сохраняемый журнал квоты. Не удалять его для повторного прогона. Записывать модель, фактические результаты и возвращённые счётчики токенов; не экстраполировать стоимость без тарифа и usage.

Локально проверены существование выбранных gid/кластера и связей, соответствие ожидаемых планов валидатору, ограничения длины и блокировка сети на неизвестном gid. Контракт `scripts/evaluate_ai.py` проверен на синтетических ожидаемых ответах: все 12 распознаются, обратный порядок аргументов paths отвергается. Это проверка фикстур и проверяющего кода, а не прогон модели.

Набор подготовлен без API-запросов и без доступа к ключам. **Результаты живого прогона здесь не заявляются.** Модель выбирает операцию; факты и цитаты формирует локальный код. Этот небольшой открытый набор проверяет маршрутизацию и аргументы, а не точность AML-ролей, виновность клиентов или обобщённое качество модели. Для сравнения моделей сохраняйте исходный набор и честно показывайте ошибки, не исправляя ожидаемые ответы под результаты.
