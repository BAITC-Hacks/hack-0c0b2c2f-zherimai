# Проверка чувствительности

`aml.sensitivity.analyze_sensitivity(features_df, graph, projection)` возвращает
`(summary, per_node, scenarios)`. Исходные DataFrame и графы не изменяются.
Метод не использует API, новые зависимости или размеченные истинные роли.

## Сообщества

Повторяем Louvain на **той же** ненаправленной проекции, которую вернул
`assign_clusters`: встречные суммы складываются, вес — `log1p(sum_kzt)`,
resolution=1. Меняется только случайный seed: 42, 43, 44, 45, 46. Изоляты
исключены. Результат каждого запуска сравниваем с исходным `cluster_id`,
совмещая узлы по точным gid; номера сообществ сами по себе значения не имеют.

Для таблицы пересечений сообществ `n_ij` обозначим:

- `T = C(n,2)` — число пар узлов;
- `A = Σ_i C(n_i,2)`, `B = Σ_j C(n_j,2)` — пары внутри групп двух разбиений;
- `I = Σ_ij C(n_ij,2)` — пары, оставшиеся в одной группе в обоих разбиениях.

`ARI = (I − A×B/T) / ((A+B)/2 − A×B/T)`. Счётчики вычисляются целыми числами,
без sklearn; идентичные вырожденные разбиения получают 1. ARI допускает
отрицательные значения. Обычное согласие пар равно `(T − A − B + 2I)/T`.
Оно может быть высоким из-за большого числа пар в разных сообществах, поэтому
не заменяет ARI.

Для узла `g`: сравниваем всё его исходное сообщество `C(g)` с сообществом
`C_s(g)`, в котором он оказался при seed `s`. Jaccard равен
`|C(g)∩C_s(g)| / |C(g)∪C_s(g)|`.

В `per_node`:

| Поле | Смысл |
|---|---|
| `cluster_stability` | Средний membership Jaccard по seed 43–46; seed 42 исключён |
| `cluster_stability_min` | Минимальный membership Jaccard по тем же четырём запускам |
| `cluster_stability_scope` | `observed_community` либо `isolate_not_assessed` |

У изолятов оба числа технически равны 1, **но устойчивость для них не оценена**.
Они исключены из сводных показателей. При отсутствии наблюдаемых узлов средний
Jaccard в summary равен `null`. `summary.louvain.membership_jaccard_min` — минимум
**среднего** Jaccard по узлам, а не минимум отдельного запуска.

## Приоритет проверки

Исходные пять коэффициентов: роль 0,30; достижимость от seed 0,25; объём 0,20;
PageRank 0,15; паттерны 0,10. Используются уже рассчитанные слагаемые
`priority_*`, делённые на соответствующий исходный коэффициент.

Для каждого коэффициента отдельно берём множители 0,8 и 1,2. После изменения
нормируем **все** коэффициенты так, чтобы сумма снова равнялась 1. Например,
увеличение 0,30 в 1,2 раза даёт после нормировки `0,36/1,06`, а не 0,36.
Признаки, роли, пороги, исходная нормализация признаков и скидка seed=0,6
не меняются. Скора округляются до восьми знаков; равенства разрешает меньший gid,
как в основном ранжировании. Gid не переводятся в float.

Всего 11 сценариев: исходный плюс 10 вариантов. Каждый топ сравнивается с
исходным: число общих узлов, доля `intersection/k`, Jaccard `intersection/union`.
Для маленьких тестовых графов `k=min(20,n)`.

| Поле `per_node` | Смысл |
|---|---|
| `priority_baseline_rank` | Место в исходной очереди |
| `priority_top20_frequency` | Доля из всех 11 сценариев, в которых узел входит в топ-20 |
| `priority_min_rank`, `priority_max_rank` | Лучшее и худшее место по 11 сценариям |

`summary` содержит только типы, совместимые со строгим JSON. В `scenarios`
16 строк: 5 с `family=louvain`, 11 с `family=priority`. Поля, неприменимые
к семейству строки, пустые; это не пропущенные вычисления. Сценарии приоритета
также содержат все фактические нормированные `weight_*`.

## Измеренный результат на текущих данных

На предоставленных 2 248 узлах, исходных ролях/приоритете из `out/nodes_roles.csv`
и проекции текущего `assign_clusters` анализ занял **0,40 секунды**
(macOS ARM64, Python 3.13.2; время только этой функции, без чтения данных).
Результаты требуют пересчёта после изменения входа или методики.

| Seed | Сообществ без изолятов | Модулярность | ARI к исходному разбиению |
|---|---:|---:|---:|
| 42 | 48 | 0,791601 | 1,000000 |
| 43 | 43 | 0,789926 | 0,677527 |
| 44 | 49 | 0,786620 | 0,675874 |
| 45 | 45 | 0,789711 | 0,689551 |
| 46 | 49 | 0,792545 | 0,670717 |

Оценены 2 229 узлов; 19 изолятов исключены. Средний membership Jaccard —
**0,6576**. Близкая модулярность не означает одинаковый состав групп:
принадлежность к сообществу нужно использовать как исследовательскую подсказку.

При отдельных изменениях весов исходный топ сохраняет **18–20 из 20 узлов**
(в среднем 19,5; минимальный Jaccard 0,8182). 18 узлов входят в топ во всех
11 сценариях; всего в топах встретились 22 разных узла. Это устойчивость
очереди к данным умеренным изменениям весов, а не проверка истинности ролей.

## Границы вывода

- Чувствительность **порогов ролей не измерена**. Роли остаются фиксированными.
- Не варьируются resolution, тип проекции, недостающие переводы и несколько
  весов одновременно. Пять seed не перебирают все возможные разбиения.
- Устойчивость не является точностью, вероятностью нарушения или доказательством
  общности преступной цели. Истинной разметки нет.
- Изменять исходные пороги или подбирать число сообществ под желаемый ответ
  по этому отчёту нельзя; слабая устойчивость показывается как ограничение.

Проверка: `python -m unittest tests.test_sensitivity -v` — десять тестов:
независимость от названий кластеров, перемещение узла, отрицательный ARI,
исключение изолятов, нормировка, порядок строк, точность больших gid,
сохранение скидки seed и отказ при несогласованном входе.
