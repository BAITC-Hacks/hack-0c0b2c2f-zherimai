# Как использовать бюджет до 200 USD

Капитан разрешил бюджет до 200 USD на работу над решением и проверки AI. Это потолок, а не цель израсходовать баланс. Не оцениваем пользу по числу запущенных агентов или длине reasoning: у каждой работы должен быть конкретный артефакт и проверка.

## Практический порядок

1. Основная работа Codex: интеграция, поиск конкретных ошибок, независимая проверка методики и кода. Параллельно только непересекающиеся ограниченные задачи; не давать нескольким агентам одновременно переписывать один модуль.
2. Все графовые метрики, схемы CSV, пересчёты, чувствительность и регрессии выполняются локально. Не отправлять модельный запрос для операции, которую точно выполняет программа.
3. Дополнительный AI-помощник использует модель только для выбора разрешённого действия по вопросу. Граф, финансовые суммы и результаты инструментов модели не требуются. Один online запрос на вопрос, без автоматических повторов; длина вопроса и выхода ограничены.
4. Сначала выполнить небольшой набор проверок запросов. Расширять его только после конкретных ошибок, а не запускать сотни одинаковых вопросов. Повторно использовать локальные результаты там, где вход не изменился.
5. Сохранить запас на исправление блокеров после интеграции и проверку запуска. Презентационные украшения и замена стека ниже приоритетом, чем обязательные результаты.

## Что реально ограничено

У нас нет подтверждённого остатка API-баланса или доступа к биллингу аккаунта. Сумма 200 USD — сообщённый капитаном доступный бюджет. Не писать «потрачено 0» или иной долларовый расход без данных Platform: текущая работа Codex тоже может тарифицироваться через API.

В optional online-помощнике реализованы постоянный локальный лимит 20 попыток, не более одного запроса на вопрос, 1 024 выходных токена и журнал возвращённых token usage. Это ограничивает запросы именно этого помощника, но **не** суммарные расходы всех Codex команды и не является измерением USD. Увеличение квоты допускается явно; не повышать её без конкретного набора полезных проверок. Реальных запросов именно этого модуля при его разработке не выполнялось. Подробности: [ai-assistant.md](ai-assistant.md).

В OpenAI Platform лимиты организации/проекта и уведомления различаются: для остановки запросов нужен hard spend limit, одно уведомление не останавливает трафик. Проверка лимита не мгновенная, поэтому возможен небольшой перерасход. Источник: [официальные spend limits](https://developers.openai.com/api/docs/guides/spend-limits), проверено 23.09.2026. Текущие настройки аккаунта здесь не менялись.

Для отдельного приложения используйте ключ ограниченного проекта и только локальную переменную OPENAI_API_KEY, не коммит и не чат. Вход Codex по API сам по себе не означает, что ключ доступен Python-приложению. На момент проверки окружения переменная отсутствовала; live-проверка помощника без неё не считается выполненной.

## Признаки неэффективной траты

- Параллельные агенты дублируют одну задачу и конфликтуют в файлах.
- Модель перечитывает весь граф для каждого простого вопроса.
- Высокий reasoning используется для форматирования, запуска тестов и сортировок.
- Ошибка квоты/доступа вызывает бесконечные повторные запросы.
- Заявлено улучшение, но нет сравнения результата, теста или проверки аналитиком.

При этих признаках сократить объём запроса, уточнить конкретную ошибку и проверить решение локально до нового платного обращения.
