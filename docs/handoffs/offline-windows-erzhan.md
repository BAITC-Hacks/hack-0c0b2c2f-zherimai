# Передача C: чистая Windows-установка из локальных wheels

23.09.2026. Участник — Erzhan и Codex. Ветка `codex/qa-erzhan`; проверенная версия приложения — `ca8b43d696dfb8ea18d4f8b5b23f93ee59973d3d`. Этот QA-коммит добавляет только инструмент проверки, его тесты и протокол. Общие зависимости, интерфейс, валидатор, README и итоговые `out/` не изменены.

## Результат для команды

Зависимости установлены в новое окружение Windows исключительно из восьми локальных wheels, без pip-индекса и кэша. Расчёт выполнен из исходных parquet в отдельной распакованной копии, из которой предварительно исключён `out/`. Повторный расчёт и независимый аудит прошли. Сохранён локальный переносимый ZIP для воспроизведения на Windows AMD64 с заранее установленным CPython 3.13.

Среда: Windows 11 AMD64, CPython 3.13.15, pip 26.2.1. Новый venv не использует системные site-packages; до установки в нём был только pip. Это отдельное окружение на той же физической машине, а не проверка второго компьютера.

## Изменённые файлы

- `tests/run_without_network.py`: stdlib-обёртка для script/module; устанавливает Python socket audit guard до запуска цели, сохраняет аргументы, пути импорта и код завершения. Даже перехваченная целью сетевая попытка делает проверку неуспешной.
- `tests/test_offline_runner.py`: пять subprocess-тестов — self-test, перехваченные connect/DNS, сохранение exit 7, аргументы и локальные импорты script/module.
- `docs/handoffs/offline-windows-erzhan.md` и `.json`: команды, измерения, точные версии и SHA-256 wheels/комплекта.

## Повторение из комплекта

Распаковать комплект в новую папку. Из неё выполнить PowerShell-команды при уже установленном CPython 3.13 x64:

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe tests/run_without_network.py --self-test
.\.venv\Scripts\python.exe tests/run_without_network.py -m pip --isolated install --no-index --no-cache-dir --disable-pip-version-check --find-links wheelhouse -r requirements.txt
.\.venv\Scripts\python.exe tests/run_without_network.py -m pip --isolated check
.\.venv\Scripts\python.exe tests/run_without_network.py run.py --data data --out out
.\.venv\Scripts\python.exe tests/run_without_network.py validate.py --data data --out out
.\.venv\Scripts\python.exe -W error::ResourceWarning tests/run_without_network.py -m unittest discover -s tests
.\.venv\Scripts\python.exe tests/run_without_network.py scripts/audit_top.py
```

Затем открыть `out/network.html`. Self-test должен сообщить PASS и одну намеренно заблокированную socket-попытку. В остальных командах такой счётчик означал бы проблему и ненулевой код завершения.

Локальные материалы на машине Erzhan находятся в игнорируемом `out-check/offline-windows-ca8b43d/`: протоколы `logs/`, `summary.json`, manifest, инструкции `OFFLINE-WINDOWS.md`, а также `zherimai-windows-py313-ca8b43d.zip`. Бинарный комплект и дополнительные копии parquet не добавлялись в Git. В репозитории публикуется только компактное свидетельство `.json`; доступ к ZIP через Git не подразумевается.

Его исходники соответствуют указанному коммиту без `out/`, дополнительно включены два QA-файла. ## Ограничения и следующий шаг

Audit guard — средство QA, а не системный firewall или защитная песочница. Он блокирует перечисленные Python socket events только в текущем процессе; native-вызовы вне hooks, неохваченные дочерние процессы и код запуска интерпретатора до runner не контролируются. Поэтому здесь подтверждена локальная установка без индекса/кэша и расчёт под guard, но не физическое отключение сети ОС. Установщик Python не включён; Linux/macOS и другие версии Python требуют своего wheelhouse.

Комплект фиксирует `ca8b43d`, а не будущий объединённый main. Визуальная приёмка браузера и исправления валидатора остаются отдельными задачами B/A. Следующий шаг после публикации интеграции капитаном: проверить новый commit, повторить отрицательные сценарии валидатора и полный расчёт, затем обновить комплект при необходимости. Интегратору передать эту ветку вместе с предыдущим исправлением локального помощника; строки общего TASKS обновить после интеграции.
