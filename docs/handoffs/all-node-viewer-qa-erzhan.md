# DalaAI: сверка каждой карточки и TXT с результатами расчёта

Задача C / Erzhan, 23.09.2026. Производственный код и артефакты — `5926dbd12dc233093eb9b9b726cf114692f8079c`; проверка выполнена в QA-ветке после объединения с main (`cc3a1cc`). Производственные файлы относительно этой базы не изменены.

## Закрытый пробел

Существующая DOM-регрессия выбирает девять характерных карточек. Новый отдельный QA-инструмент `tests/check_all_viewer_nodes.py` дополнительно проходит **каждый gid** предоставленного набора, проверяет поиск, CSV-поля карточки, подписи направленных соседей и содержимое сформированного TXT. Это расширение проверки согласованности представления; расчёт ролей не меняется.

Проверяются:

- полное множество gid из исходного `nodes.parquet`, уникальность CSV и HTML;
- `role`, `role_score`, `priority_score`, `cluster_id` в HTML относительно CSV; видимые роль, кластер и точность scores;
- дословные `evidence` и `next_request`, число плательщиков/получателей и операций;
- каждое направленное ребро относительно `edges.parquet`: концы, число операций и сумма в целых тиынах;
- все подписи входящих и исходящих соседей; петля показывается один раз;
- TXT для каждого узла: gid, роль, кластер, scores, объяснение, следующий запрос, суммы и контрагенты. Суммы в TXT округляются интерфейсом до целого KZT; сверяется погрешность округления, а не заявляется точность до тиына в тексте.

## Запуск

После обычного расчёта и `validate.py`, из корня репозитория с установленными зависимостями и Node.js:

```powershell
.\.venv\Scripts\python.exe -B tests/check_all_viewer_nodes.py --data data --out out
```

В macOS/Linux используйте `.venv/bin/python`. Node.js нужен только для этой дополнительной проверки. Скрипт сначала выполняет существующий `scripts/check_viewer.cjs`; его условия рассчитаны на предоставленный набор с характерными примерами ролей. Это не универсальный валидатор произвольного графа.

Проверенная среда: Windows 11 AMD64, Python 3.13.15, Node.js 24.19.0. Последняя строка успешного запуска:


## Проверка отказов

Шесть изолированных изменений в копиях артефактов завершились отказом с ожидаемой конкретной причиной:

| Подмена | Диагностика |
|---|---|
| Дописано объяснение последней строки CSV | `Exact evidence` |
| `role_score` последней строки увеличен на 0,01 | `Role score vs CSV` |
| `priority_score` последней строки увеличен на 0,0001 | `Priority score vs CSV` |
| Изменён `cluster_id` последней строки | `Cluster vs CSV` |
| Удалена последняя строка CSV | `CSV node coverage differs from parquet` |
| Последнее ребро HTML увеличено на 0,01 KZT | `Edge amount vs parquet` |

Отдельная положительная проба с согласованной синтетической петлёй прошла: **3 120 рёбер, 6 239 записей соседей**. Петля добавила одну запись. Это проверка DOM-макета и правил сверки; роли и объяснения синтетического набора через аналитический пайплайн не пересчитывались.

Всего **8 из 8 сценариев** дали ожидаемый результат: базовый, шесть отказов и петля. Исходные файлы по хешам не изменились. Сводка, диагностические причины и хеши — [в JSON](all-node-viewer-qa-erzhan.json). Полные локальные пробы и журналы сохранены у C в игнорируемом `out-check/all-node-checker-5926dbd/`.
