## 3. Приоритеты улучшений

| Приоритет | Предложение | Основание и условие приёмки |
|---|---|---|
| До сдачи | Сохранить текущие алгоритмы; завершить ручной просмотр и репетицию | Текущий набор укладывается в 300 секунд с большим запасом. Новые оптимизации не нужны для прохождения временного ограничения |
| Следующее исследование | Измерить рост точной betweenness на более крупных графах | Это крупнейшая отдельно измеренная графовая операция: 1,79 с под профилировщиком. Сравнить точные движки; приближение может изменить роли и требует отдельного согласования методики |
| После профиля на больших данных | Распространять наборы seed по DAG сильно связных компонент | Возможная замена повторных обходов с сохранением точной достижимости. Исключать собственный seed, сохранять циклы и изоляты; ускорение на текущем наборе не измерено |
| После оценки пользы | Проверить возможность переиспользования базового Louvain в анализе чувствительности | Сейчас выполняются шесть запусков, включая повтор seed 42. Повтор одновременно служит проверкой воспроизводимости; удалять его без сохранения проверки проекции и параметров нельзя |
| При росте числа транзакций | Сократить повторные проходы в FIFO-сопоставлении | Сейчас всего 0,034 с. Сохранить порядок `(дата, сумма)`, окно 1–2 дня, исключение того же дня и запрет повторного расходования исходящей суммы |
| При росте размера HTML | Уменьшить промежуточные копии при сериализации | Сейчас генерация занимает 0,097 с, память не измерена. Сохранить все поля, строковые gid, точность чисел, обработку пропусков и экранирование недоверенных строк |
| Документация | Сократить основной путь чтения README и использовать название Dala AI | Это предложение для интегратора: одна таблица актуальных проверок, история в handoff, сохранение 11 требований, порогов, формул и ограничений. README в этом коммите не меняется |

Для будущего изменения алгоритма сначала зафиксировать базовый замер на одинаковых данных и окружении; затем сравнить медиану повторных запусков и пиковую память. Ускорение нельзя оценивать сравнением обычного запуска с профилированным.

Приёмка оптимизации без изменения методики: прежние обязательные схемы, все gid и изоляты, те же роли, приоритеты, кластеры и объяснения; совпадение 7 CSV и HTML; валидатор, независимый аудит и релевантные тесты. При изменении численной реализации любое отличие сначала исследуется, а не объявляется допустимым автоматически.
