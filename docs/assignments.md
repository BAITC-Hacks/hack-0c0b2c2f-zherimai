# Назначения команды

Назначено 23 сентября 2026 по просьбе капитана немедленно распределить работу. Имена Alexandr и Erzhan взяты из истории официального репозитория; Git-авторство каждого остаётся его собственным. Это актуальное распределение вместо прежнего «решим позже».

|---|---|---|---|
| Капитан a4ns + его Codex | A: методика, приоритеты и интеграция | main для интеграции; отдельная ветка при необходимости | Следующий проверенный результат до 15:30 |

| Erzhan + его Codex | C: воспроизводимость и независимая проверка | codex/qa-erzhan | Чистый запуск или конкретная причина сбоя до 15:30 |

## A — капитан a4ns и текущий Codex

Владеет `aml/features.py`, `aml/roles.py`, `aml/priority.py`, `aml/clusters.py`, `aml/explain.py`, `aml/resilience.py`. Общие файлы `run.py`, `requirements.txt`, README, AGENTS, TEAM_CONTEXT, PLAN, TASKS и финальные `out/` также здесь.

Следующая задача: аудит топ-20 по первичным метрикам, проверка объяснений и чувствительности приоритета/кластеров. Сохранять обязательные схемы и воспроизводимость. Принимать проверенные изменения B/C, обновлять итоговые результаты и описание. Не переделывать UI параллельно с Alexandr. Финальный push и отдельную подачу на платформе контролирует капитан.

## B — Alexandr и его Codex

Владеет только `aml/viewer.py`, `aml/viewer_template.html` и при необходимости отдельными UI-проверками в `tests/test_viewer.py`. Функция `build_viewer(nodes_df, edges_df, clusters_df, out_path)` и строковые gid сохраняются.

Первое действие: получить актуальный main, прочитать AGENTS/TEAM_CONTEXT/README и открыть настоящий экран локально. При явном запрете инструмента браузера не обходить его: человек может проверить экран сам и сообщить наблюдения.

Задача до 15:30:

1. Проверить поиск произвольного координатора, изолированного seed и узла depth=4, выбранных из текущего CSV.
2. Проверить направление стрелок, входящие/исходящие связи, переход к соседу, фильтры ролей/кластеров и 1–2 шага.
3. Убедиться, что по карточке можно за минуту объяснить три названных gid: правило, фактические числа, ограничение и следующий запрос.
4. Исправить найденные ошибки и мешающие чтению элементы; основа уже работает, переписывать интерфейс с нуля не нужно.
5. Передать commit, список проверенных действий, фактические дефекты/исправления и скриншот при разрешённом доступе. Не объявлять программную DOM-проверку визуальным просмотром.

Проблему расчёта/порогов передать A, не менять их в своей ветке. Локальный вывод — `out-check/ui`, итоговый `out/` не коммитить.

## C — Erzhan и его Codex

Владеет `aml/load.py`, `aml/validate.py`, `validate.py`, `tests/test_invariants.py` и новыми отдельными QA-тестами, затем `aml/assistant.py`. Общие зависимости/README самостоятельно не менять одновременно с A: передать точное предложение интегратору.

Задача до 15:30:

1. Получить актуальный main и повторить команды README в новом окружении на своём компьютере. Зафиксировать ОС, архитектуру, Python, команды и время. Если компьютер также macOS, не называть это проверкой Windows/Linux.
2. Проверить все 2 248 gid, изоляты, scores, evidence, согласованность кластеров, топ и запрет terminal на depth=4.
3. Выполнить существующие тесты. Добавлять только тест на конкретный найденный пробел, а не дублировать формулы.
4. Проверить помощника: неизвестный gid, путь, общие получатели, кластер, неподдерживаемый вопрос; никаких выдуманных ответов.
5. Передать commit исправлений или отчёт с фактическим результатом. При проблеме установки указать точную ошибку и совместимый вариант; версии не обновлять вслепую.

После прохождения P0 можно улучшать локальный помощник. Подключение внешнего LLM — отдельный следующий этап с проверяемым доступом, согласованным объёмом данных и сохранением offline режима; сейчас не тратить время на ожидание ключа. Локальный вывод — `out-check/qa`.

## Общая передача

Каждый работает от собственного Git-аккаунта и сообщает капитану: ветку/commit, изменённые файлы, проверки, ограничения. Детали — `docs/team-workflow.md`. Агент не видит чаты других участников: всё важное передать коммитом или коротким сообщением капитану. Ветки отправлять в этот же официальный репозиторий. Не использовать force push и не переписывать чужие изменения.
