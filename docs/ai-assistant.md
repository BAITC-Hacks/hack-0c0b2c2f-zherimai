# Опциональный AI-помощник с локальными вычислениями

`aml.ai_assistant` добавляет семантический выбор операции к существующему `AnalystAssistant`. Модель выбирает ровно один инструмент; сам инструмент читает граф на ноутбуке. Объяснение составляется по локальным результатам шаблоном, с точными строковыми gid, evidence и ссылками на таблицы. Модель не присваивает роли, не меняет приоритеты и не пишет выводы о клиентах.

## Запуск

Сначала выполнить основной расчёт по README, чтобы появились `out/nodes_roles.csv` и `out/clusters.csv`. Базовый помощник работает без ключей и интернета:

```sh
.venv/bin/python -m aml.ai_assistant --question 'Кластер 1' --data data --out out
```

Он явно возвращает `mode: offline_deterministic` и `fallback_reason: online_not_enabled`. Для карточки, пути и общих получателей в вопрос надо подставить реальные gid из текущего CSV; они всегда остаются строками.

Для онлайн-планирования отдельно задать `OPENAI_API_KEY` и `OPENAI_MODEL` в окружении терминала. Не передавать ключ аргументом команды, в вопросе или в Git. `.env` автоматически не читается. Модель намеренно не зафиксирована: выбирается доступная вашему API-проекту модель с поддержкой Responses API и strict function calling.

```sh
.venv/bin/python -m aml.ai_assistant --online --question 'Сводка сообщества номер 1' --data data --out out
```

Без `--online`, ключа либо модели сетевого запроса не будет. Бюджет Codex и API-запросы этого помощника — разные источники расхода: данный журнал учитывает только вызовы помощника.

## Что получает API

Только текст вопроса после замены каждого указанного gid длиной 15–20 цифр на `node_1`, `node_2` и т. д., список разрешённых псевдонимов и схему инструментов. Соответствие `node_1 → исходный gid` остаётся локальным. Повтор одного gid получает тот же псевдоним.

CSV, parquet, метрики, evidence, результаты инструментов и весь граф не включаются в запрос. Содержимое остального текста вопроса отправляется как введено; замена gid **не является общей анонимизацией произвольного текста**. Не вставляйте в вопрос имена, ключи или скопированные строки банковских данных. Вопрос с неизвестным локальным gid сразу обрабатывается локально; сеть для его поиска не нужна.

Используется фиксированный `https://api.openai.com/v1/responses`, `store: false`; HTTP-перенаправления отключены. `store: false` отключает сохранение состояния ответа, но не является обещанием полного отсутствия хранения у провайдера: применимы настройки проекта и политика обработки данных. См. [официальную документацию OpenAI по данным](https://developers.openai.com/api/docs/guides/your-data).

## План и защита от неверного исполнения

В strict function `plan_query` все поля обязательны, лишние запрещены:

- `action`: `get_node`, `paths`, `common_receivers`, `cluster_summary` или `help`;
- `node_refs`: список псевдонимов только из текущего вопроса;
- `cluster_id`: целое число либо `null`.

Локальная проверка дополнительно ограничивает число и смысл аргументов: пути требуют двух разных узлов, общие получатели — минимум двух, кластер — номера без узлов. Явный номер после «кластер», «сообщество», `cluster` или `community` ограничивает допустимый `cluster_id`: вопрос «Кластер 1» не может исполнить план для кластера 2. Остальные числа и gid не считаются номерами кластеров. Подмена имени инструмента, неизвестный псевдоним, повторные ссылки, лишнее поле, несколько вызовов, отказ или незавершённый ответ вызывают честный локальный fallback с кодом причины. Произвольный текст модели не показывается как факт. Единственный допустимый результат планирования — проверенная структура; shell, доступ к файлам и внешние инструменты модели не предоставлены.

Ответ содержит `mode`, проверенный `plan` с псевдонимами, локальный `result`, шаблонный `answer`, `evidence`, `citations` и ограничение интерпретации. `citations` указывает точный gid в `nodes_roles.csv`; для пути — также пары `src/dst` в `edges.parquet`, для общих получателей — каждую пару «источник → общий получатель», для кластера — номер в `clusters.csv`. У `help` и ошибок нет выдуманных ссылок. Обрывы HTTP возвращают безопасную причину `api_network_error` без текста ответа провайдера и повторной попытки; израсходованный слот квоты сохраняется.

## Ограничение расхода

- Не более одного HTTP-запроса на вопрос; повторных попыток и второго запроса с результатами инструмента нет.
- До 2 000 символов и 8 различных gid в вопросе.
- `max_output_tokens=1024`, сетевой timeout 30 секунд, ответ не более 256 KiB.
- По умолчанию не более **20 попыток суммарно**, включая ошибки и прерванные запросы. Резервирование слота происходит атомарно в SQLite **до** сети и сохраняется между запусками; конкурентные процессы не превышают общий лимит одного журнала.
- Журнал — `out-check/ai-usage.sqlite`, он уже исключён из Git. В нём только время, статус и возвращённые API счётчики токенов. Вопросы, gid, ответы модели и ключи не сохраняются.
- Явный `--max-calls N` допускает повышение общей квоты до 200, `--usage-db PATH` меняет локальный журнал. Это технический лимит помощника, не долларовый лимит API-аккаунта; смена/удаление журнала или использование другого каталога создают отдельный счётчик. Не сбрасывайте журнал для обычных повторов.
- `api_usage` содержит только фактические счётчики API, включая reasoning/cached tokens, если они возвращены. При отсутствии данных выводится `null`; стоимости в долларах не выдумываются. При сетевой ошибке расход может быть неизвестен, поэтому слот не возвращается.

Лимит выходных токенов включает скрытые reasoning tokens. На некоторых моделях 1 024 токенов может не хватить на завершённый план: тогда будет локальный fallback и расход отразится только при наличии `usage`. Это сознательное ограничение демонстрационного бюджета. Официальные источники: [function calling](https://developers.openai.com/api/docs/guides/function-calling), [Responses API](https://developers.openai.com/api/reference/python/resources/responses/methods/create).

## Проверка

```sh
.venv/bin/python -m unittest discover -s tests -p 'test_ai_assistant.py' -v
```

Тесты подменяют HTTP: проверяют границу обезличивания gid, фиксированный endpoint, strict-схему, исполнение локальных операций, неизвестные ссылки, отказы/незавершённые ответы, fallback, отсутствие повторов, безопасные ошибки и устойчивую к конкурентным запускам квоту. Это не проверка качества конкретной модели или доступности реального API. Платный API-вызов при разработке этого модуля не выполнялся.
